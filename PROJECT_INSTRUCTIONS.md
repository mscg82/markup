# Project instructions: Markup (serverless image-annotation web app)

## Goal
Maintain and extend "Markup", a fully client-side web app for drawing over a background image. Static hosting only; all logic and state live in the browser. Primary target: Chrome (desktop and Android); must also work on mobile browsers (Firefox on Android tablets included).

## Files (uploaded as project knowledge)
index.html (markup), css/style.css, js/markup.js (app logic), js/colorpicker.js (custom color picker), js/i18n.js, locale/languages.json (selectable languages) and locale/*.json (all user-visible strings; never hard-code text in HTML or JS, add a key to locale/en.json and use data-i18n* attributes or t()), sw.js (service worker, must stay in the root for scope), manifest.webmanifest, img/ (favicon.ico/svg, icon-48/96/144/192/512, icon-maskable-512, apple-touch-icon), README.md.

## Architecture rules
- No backend, no build step, no external dependencies. Keep the structure: markup in index.html, styles in css/style.css, logic in js/markup.js.
- Background is an unmodifiable canvas (downscaled to max 2400 px). Drawing goes on a separate transparent layer canvas.
- History = list of vector operations {t: pen|line|rect|circle|erase|stencil|..., c, w, points}. Undo pops the last op and replays the rest. The eraser is an op using destination-out on the drawing layer only.
- Zoom/pan = scale + offset (s, ox, oy) applied at render time. Pointer events for mouse/touch/pen; two-finger pinch zooms and pans; Move tool, Space, right/middle mouse and arrow keys also pan.
- Clear button: click = clear drawing (keeps the resize/frame/crop ops in the history, only non-resize ops are removed), long press (700 ms) = also remove background; both use confirm() and are not undoable.
- Export: merge background + layer at full resolution to JPEG.
- localStorage keys: markup.bg (JPEG data URL), markup.ops (operations JSON), markup.prefs (color, draw width, erase width). Always wrap storage access in try/catch and warn the user if saving fails.
- Offline: sw.js uses stale-while-revalidate. When a cached file is added, add it to ASSETS. Version rule: CACHE in sw.js (currently markup-v36) and APP_VERSION in js/markup.js (shown in the app's bottom-right corner) always change together, and only (1) in the first code change after the owner announces that a new development cycle has begun, or (2) when the owner explicitly asks for a bump. Never bump them at any other time.
- Icons: Firefox Android ignores SVG for shortcuts, so keep raster icons and favicon.ico declared before the SVG in <head>.

## Working style
- When changing the app, edit the existing files rather than rewriting them, and list which files changed and need re-uploading.
- Keep the UI compact and touch-friendly (min 36 px tap targets), and keep it working on narrow screens.
- Say plainly when something has not been tested on a real device.

## Ideas not yet done
fill option for shapes, remembering the selected tool, text tool, offline update notification.

## Code conventions
- When converting a value to a number with unary plus in an assignment, always write `a=(+b)`, never `a=+b`, so it is not mistaken for `+=`.

- Snapshots: stored in localStorage `markup.snapshots` (array of {id,name,created,enc,data}; data = deflate+base64 of JSON {operations,preferences}, enc 'deflate', or plain JSON with enc 'json' when CompressionStream is missing). The background is NOT stored: it is always markup.bg, valid because every action that replaces the background calls resetSnapshots() (Open image, Empty image, Clear short/long, Import status). Restoring a snapshot only replaces ops/preferences and replays. Entries in older formats are dropped at load.
- js/diag.js: optional touch-diagnostics panel, enabled by settings.diag (Settings checkbox). It listens on window in the capture phase (passive) and never changes events. markup.js tells it about changes with the 'markup:diag' event; its close button fires 'markup:diag-closed'.
- Palm rejection lives in js/markup.js (palmOn, palmDown, palmUp, palmReset; settings.palm default false, settings.palmMs default 250). Every hook is guarded by `palmOn` first so the off state costs one boolean test; rejected pointers are kept in palmRej and never enter `ptrs`. Size ratios (0.6, 1.8) and the 1 s after-window are constants, not settings.

- Resize background: resampleCanvas(src,w,h,sharp) in js/markup.js. The 'scale' op carries `s` (0 legacy bicubic, 1 normal, 2 strong Lanczos-3 + clamped unsharp). Never change what s=0/missing produces, because saved histories replay it.
- Resize operations are 'frame', 'scale' and 'crop' ({x,y,w,h}); isResizeOp() lists them and bgStep(b,o) computes the background after one of them. replay() starts from bgCache (the background after the leading run of resize ops, valid while bg0 and those op objects are unchanged) so drawing-time replays never redo resizes; call syncBgCache() after applying a resize op directly. Crop mode state is the `crop` variable (cleared by replay/setBackground/render without bg).
- Spotlight: the crop selector (`crop` object, startSelect(kind) with cropKind 'crop'|'spot') also creates the spotlight; the floating box is #spot (spotBox/spotCv, state `spot`), created by createSpot(), a live view (not a picture): drawSpot() redraws it from bg/L (scheduled by render()), and spotRect() shifts its region through the frame ops in the history (resizeChain()) so it follows Resize frame and its undo/redo; any scale/crop op or a new bg0 closes it via dropSpot(). Never stored in ops/status/snapshots. The global `canvas` CSS rule is overridden for #spot canvas.
- Drawing through the spotlight: onDown/onMove (the canvas pointer handlers) are also attached to #spotCv; `viaSpot` (set at the top of each handler) switches toImg() to the box's mapping (spotRect()), `spotId` is the pointer drawing through it. Gestures (pinch, pan, temp zoom/move, eraser outline) stay canvas-only.

- Stencils (v31): op {t:'stencil',k:'x'|'circle'|'tri'|'square'|'char',ch?,c,w,cx,cy}; the box is a square of side w centred on (cx,cy); stroke thickness is a fraction of w (ST_X, ST_RING, ST_TRI) so the filled/empty ratio stays constant. One remembered width per tool (v32): `widths[key]` with WKEYS = pen, line, arrow, rect, circle, star, erase, stencil.x|circle|tri|square|char (wkey() gives the current tool's key, WMAX the limit: 200 for stencils, 80 otherwise). Persistence: `markup.prefs` {color,widths,sharp}, status `version:2` with preferences {color,widths}, snapshots the same. applyWidths(w,leg) restores them and also reads the legacy single widths (prefs draw/erase/stencil; status/snapshot drawWidth/eraseWidth/stencilWidth), applied to every tool of the group before the per-tool values; keep that backward compatibility. An erase op may carry d:[indices of stencil ops] it deleted by touching their bounding box; when the erase op is drawn (live or in replay) wipeStencils(d) redraws those stencils with destination-out, 1 px wider (drawStencil(c,o,g)), so the deletion happens at its own place in the history: earlier fills and strokes saw the stencil, later ones do not, and whatever the stencil covered (pen strokes, fills) is cleared too. deadStencils() only tells the eraser which stencils are already deleted. Deletion, undo and redo are one history step.

- Left toolbar controls (v32): layoutWidth() adds `vexp` to the header when the toolbar is on the left and the expanded controls fit (header.scrollHeight <= clientHeight). In `vexp` the `.gw` group is a 2-column grid: left the color button #cp (its popup keeps square/hue/hex only: the palette inside it is hidden) with the quick palette #sw below it (reused, 2 columns of 28 px circles); right #wv above the width slider #width (inside `.wslot`), which is rotated -90deg (a transform, which works in old Chrome, unlike vertical range inputs) and is as tall as the palette. If it does not fit, `vexp` is removed and `wpop` added (buttons with popups, as before). Top toolbar: unchanged (`wpop` only when the inline slider is shorter than MIN_INLINE_WIDTH).
- layoutWidth() returns at once while #wv or #wvPop has the focus (the on-screen keyboard shrinks the window and would collapse the controls under the user's fingers); a blur listener re-runs it afterwards.
- Colors (v32): remembered per tool like the widths: `colors[key]` for CKEYS = WKEYS without erase, plus fill; ckey() gives the current tool's key (null for erase/pan), curCKey is the tool the color controls edit, loadToolColor() runs when a tool is chosen, colorChosen(c) when the user picks a color, syncColor() shows colors[curCKey]. Persisted in `markup.prefs` {color,colors,...}, status/snapshot preferences {color,colors,widths}; applyColors(c,leg) also reads the legacy single `color` (applied to every tool first). The hidden #color input always mirrors the current tool's color, so drawing code keeps reading it.
- Two letter stencils (v32): menu items data-k="char" (Letter 1) and "char2" (Letter 2). Both create ops with k:'char' (the saved format is unchanged); only the UI key differs (`stencil.char`, `stencil.char2` in WKEYS/CKEYS), so each remembers its own width and color. The typed character (stencilChar) is shared.

- Murdoku mode (v33, setting `murdoku` in markup.settings): when an X mark stencil is committed in `end()`, murdokuHits(o) lists the live non-X stencils whose box overlaps it and stores them as `d` on the stencil op (same field and mechanism as the erase op's `d`). replay()/commit/redo call wipeStencils(o.d) BEFORE drawing any op with `d`, so the deleted stencils are cleared at that point of the history and the X is drawn over the gap; deadStencils() collects `d` from every op. Nothing is deleted while dragging (the preview is drawn on the overlay only). validOp accepts `d` on stencil ops.
- Murdoku mode, letters (v34): Letter 2 stencils are saved as k:'char' with `lt:2` (Letter 1 has no `lt`; validOp accepts lt only as 2 on a char). murdokuHits(o) now handles two cases: an X mark (every live non-X stencil whose box overlaps) and a Letter 1 (every live Letter 2 whose box overlaps, plus every live Letter 2 with the same `ch` anywhere). The result is the stencil op's `d`, handled as in the v33 note above.
- Murdoku mode, Letter 1 (v35): murdokuHits() for a Letter 1 now returns every live stencil of any kind whose box overlaps the new one (X marks and other Letter 1 included), plus every live Letter 2 with the same `ch` anywhere. The X mark rule is unchanged.

- Resize background (v35): the resampling is plain functions (lanczos, cubic, cubicWeights, unsharp, resamplePixels) so resampleAsync() can build a Web Worker from their toString(). applyScaleDialog() shows the #busy overlay (spinner + Cancel), runs the worker, stores the result in scaleCache and then applies the op, which finds it cached. Without Worker support it falls back to the synchronous resampleCanvas(). Replaying a history that contains a scale op (undo past it, import, reload) is still synchronous.

- Paste image (v36): the #file change handler and the window 'paste' listener both call openImageFile(f) (confirm.openImage warning, or confirm.pasteImage for a paste, when there is work, then setBackground etc.). The paste listener ignores events while a dialog is open or the #busy overlay is shown, and only reacts to clipboard items of kind file with an image/* type.
